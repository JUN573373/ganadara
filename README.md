#  발주체크 웹 도구

기존 발주 엑셀을 불러와 날짜별 발주체크표로 정리하고, 사용자가 내용을 수정한 뒤 원하는 형식의 엑셀을 내려받는 웹 프로젝트입니다.

GitHub Pages 배포를 목표로 합니다. 현재는 기존 코드와 참고 파일을 분석해 작성한 설계 단계이며, 웹 화면과 변환 기능은 아직 구현하지 않았습니다.

## 1. 구현 가능 여부와 범위

**엑셀 불러오기 → 자동 정리 → 사용자 편집 → 엑셀 다운로드는 GitHub Pages에서 구현할 수 있습니다.**

GitHub Pages는 HTML·CSS·JavaScript를 제공하는 정적 호스팅입니다. 엑셀 처리를 사용자 브라우저에서 수행하면 별도 처리 서버 없이 사용할 수 있습니다. [GitHub Pages 공식 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

기존 프로그램의 외부 사이트 로그인·발주 수집까지 포함한 전체 대체에는 추가 검토가 필요합니다.

| 기능 | 구현 방향 |
| --- | --- |
| 기존 엑셀 읽기, 여러 파일·시트 합치기 | 브라우저에서 처리 |
| 날짜별 분류, 발주 합치기, 필드 편집 | 브라우저에서 처리 |
| 서식이 있는 엑셀 생성·다운로드 | 브라우저에서 처리 |
| 외부 사이트 로그인 및 발주 수집 | 사이트의 공식 연동 방법과 브라우저 접근 허용 여부 확인 필요 |
| 여러 사용자의 작업 공유·동기화 | 필요해지면 별도 저장소와 인증 구조 검토 |

브라우저의 외부 사이트 요청에는 CORS, 즉 다른 출처의 요청을 대상 서버가 허용하는 정책과 로그인 쿠키 제약이 적용됩니다. 현재 대상 사이트의 허용 여부는 검증하지 않았습니다. 직접 연동이 허용되지 않으면 승인된 API나 별도 백엔드 등 다른 연동 수단이 필요하며, GitHub Pages 자체에서 기존 Node.js 수집 프로그램을 실행할 수는 없습니다. [MDN CORS 문서](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)

**첫 버전은 기존 엑셀을 입력받아 수작업 정리 과정을 자동화하는 범위로 제안합니다.** 이 단계에서는 원본 엑셀을 확보하는 경로가 계속 필요합니다. EXE 사용까지 완전히 없애려면 원본 수집 경로를 후속 단계에서 확정해야 합니다.

## 2. 기존 자료에서 확인한 내용

### 기존 프로그램: `sg_pj-main`

- `package.json`의 실행 진입점과 개발 명령은 `another.js`를 사용합니다.
- 외부 발주 사이트에 로그인한 뒤 목록과 상세 발주서를 읽습니다.
- 검색 유형은 리허설·촬영용과 예식일로 구분합니다.
- 시작일과 종료일을 입력받아 엑셀을 생성합니다.
- 코드상 목록 수집은 상태에 `확인`이 포함된 행을 만나면 중단됩니다. 따라서 생성 파일을 전체 발주 목록으로 단정하지 않습니다.
- 배송시간과 본식 부토니에 항목은 빈 값으로 생성됩니다.
- `credentials.js`를 참조하지만 전달된 폴더에는 해당 파일이 없습니다. 이번 분석에서는 프로그램을 실행하거나 실제 로그인하지 않았습니다.

### 입력 예시

`참고/예식일_2026-09-12_to_2026-09-12.xlsx`

| 시트 | 데이터 행 수 | 구조 |
| --- | ---: | --- |
| 아이니 | 37 | 발주코드 등 10개 열 |
| S웨딩 | 5 | 아이니와 같은 열 구조 |

입력 열:

`발주코드 / 담당플래너 / 신부명 / 배송지 / 배송시간 / 발주부케 / 부토니에 / 특이사항(기타사항) / 예식장소 / 예식시간`

이 예시에는 **행별 예식 날짜가 없습니다.** 파일명은 단일 날짜를 나타냅니다. 여러 날짜를 조회한 파일도 같은 구조라면 파일명에 있는 기간만으로 각 행의 날짜를 복원할 수 없습니다.

전달된 코드의 출력 시트명은 `Sheet 1`이지만 참고 파일에는 `아이니`, `S웨딩`이 있습니다. 시트 분리 과정은 현재 코드만으로 설명되지 않으므로, 가져오기 기능은 특정 시트명을 고정하지 않고 열 이름을 기준으로 판별해야 합니다.

### 목표 예시

`참고/2026_발주체크__0909_0915_v00.01.XLSX`

| 시트 | 데이터 행 수 | 주요 구조 |
| --- | ---: | --- |
| 9.12(토) | 29 | 날짜 제목, 열 제목, 번호를 포함한 본식 발주표 |
| 9.13(일) | 11 | 본식 발주표 |
| 촬영 | 6 | 날짜를 포함한 촬영 발주표 |

행 수는 제목과 빈 서식 행을 제외하고 신부명이 있는 데이터 행을 센 값입니다. 목표 파일에는 수식과 병합 셀이 없으며, A4 가로 인쇄 설정이 있습니다. 표의 색상·글꼴·열 너비·행 높이는 구현 시 별도로 비교해 재현합니다.

### 비교 결과와 해석

- 입력 42행을 담당플래너·신부명·예식장소·예식시간으로 비교하면 29개 그룹이 됩니다. 비교 시 앞뒤 공백과 플래너명의 `-S웨딩` 표시 차이를 정리했습니다.
- 이 29개 그룹은 목표 파일의 `9.12(토)` 29행과 대응합니다.
- 여러 발주를 한 행사 행으로 합치는 작업이 있는 것으로 추정됩니다. 정확한 합산·병합 규칙은 아직 확정되지 않았습니다.
- 일대일로 대응하는 행에서도 부케명, 특이사항, 배송지 등의 변경이 확인됩니다. 원본만으로 모든 수정 내용을 계산할 수 있다고 보장할 수 없습니다.
- 제공된 원본은 9월 12일 예식 자료입니다. 목표 파일의 9월 13일 예식과 촬영 데이터를 재현하려면 해당 원본이나 수동 입력이 추가로 필요합니다.

## 3. 목표 사용 흐름

1. **엑셀 불러오기**
   - 하나 이상의 `.xlsx` 파일과 사용할 시트를 선택합니다.
   - 대문자 `.XLSX` 확장자도 처리합니다.
   - 시트별 출처와 본식·촬영 구분을 확인합니다.
2. **날짜와 정리 기준 설정**
   - 작업 연도, 시작일, 종료일을 지정합니다.
   - 날짜가 없는 입력에는 파일별 또는 행별 날짜를 지정합니다.
   - 발주 합치기 후보와 부케명 변환 규칙을 검토합니다.
3. **미리보기에서 편집**
   - 날짜·출처·배송지 등으로 필터링하고 행 순서를 정합니다.
   - 배송지, 배송시간, 부케명, 부토니에, 특이사항 등을 수정합니다.
   - 행을 추가하거나 출력에서 제외하고, 합친 행을 다시 나눌 수 있게 합니다.
4. **출력 설정**
   - 포함할 날짜·촬영 시트, 표시 열, 정렬, 글자 크기, 열 너비와 인쇄 방향을 선택합니다.
   - 기본 출력은 참고 파일의 열 순서와 시트 구성을 따릅니다.
5. **엑셀 다운로드**
   - 미확인 날짜와 충돌 항목을 확인한 뒤 파일을 생성합니다.
   - 파일명 예시: `2026_발주체크__0909_0915_v00.01.xlsx`
   - 연도, 기간, 업체명, 버전 표기는 사용자가 변경할 수 있게 합니다.

## 4. 변환 규칙 초안

아래 규칙은 구현 제안입니다. 실제 업무 규칙으로 검증한 뒤 확정합니다.

| 항목 | 기본 처리 | 사용자 제어 |
| --- | --- | --- |
| 출처 | 원본 파일·시트·행 번호와 발주코드를 내부에 보존 | 출처 이름 및 표시 방식 변경 |
| 날짜 | 행의 날짜 우선, 없으면 단일 날짜 파일명에서 제안 | 제안 날짜 확인 및 파일별·행별 지정 |
| 여러 날짜 파일 | 행별 날짜가 없으면 미확정 표시 | 날짜 지정 후 시트 분류 |
| 본식 발주 합치기 | 출처·날짜·플래너·신부·장소·시간을 이용해 후보 제안 | 원본 발주 목록 확인 후 합치기·분리 |
| 같은 파일 재입력 | 출처·발주코드와 실제 내용을 비교해 중복 또는 변경 후보 표시 | 유지·제외·갱신 선택 |
| 출력 번호 | 본식 시트의 최종 행 순서에 따라 1부터 부여 | 정렬·행 순서 변경 |
| 담당플래너 | 원본 이름 보존 | 출처 접미사 표시 여부 설정 |
| 배송지 | 원본과 `확인필요` 표시 유지 | 실제 배송지 확인 후 수정 |
| 배송시간 | 빈 값 유지 | 직접 입력, 업무 규칙 확정 후 자동 계산 검토 |
| 발주부케 | 원문 보존, 등록된 변환 규칙으로 표시명 제안 | 상품명 매핑·직접 수정·금액 표시 설정 |
| 부토니에 | 입력값 유지, 없으면 빈 값 | 직접 입력 |
| 특이사항 | 출력 열 이름을 `특이사항`으로 정리하고 원문 보존 | 편집 및 여러 발주 메모 합치기 |
| 원본에 없는 행 | 자동 생성하지 않음 | 수동 추가 또는 다른 원본 가져오기 |

같은 신부의 추가금·추가상품 발주는 서로 다른 유효 발주일 수 있습니다. 이름이 같다는 이유만으로 삭제하거나 금액을 버리지 않습니다. 합친 행에도 원본 발주 목록을 연결하고, 배송지·시간 등이 충돌하면 사용자가 값을 선택하게 합니다.

부케의 실제 품종·디자인과 별도로 전달받은 요청은 원본의 상품 등급이나 가격만으로 확정하지 않습니다. 사용자가 관리하는 변환표 또는 직접 입력으로 보완합니다.

편집 데이터는 원본과 구분해 보관하며, 정렬이나 필터를 바꿔도 수정 내용이 다른 행으로 이동하지 않도록 고정 식별자를 사용합니다.

## 5. 엑셀 출력 기본 형식

### 본식: 날짜별 시트

- 시트명 예시: `9.12(토)`
- 첫째 행: 날짜 제목
- 둘째 행: 아래 열 제목
- 셋째 행부터: 데이터

`NO / 담당플래너 / 신부명 / 배송지 / 배송시간 / 발주부케 / 부토니에 / 특이사항 / 예식장소 / 예식시간`

### 촬영: 통합 시트

- 시트명: `촬영`
- 첫째 행: 아래 열 제목
- 둘째 행부터: 날짜순 데이터

`날짜 / 담당플래너 / 신부명 / 배송지 / 배송시간 / 발주부케 / 특이사항 / 리허설장소 / 리허설시간`

### 공통

- 참고 양식의 서식과 A4 가로 인쇄를 기본으로 시작합니다.
- 원본 발주코드는 편집 화면에서 추적할 수 있게 유지하고, 기본 발주체크 출력에서는 제외합니다.
- 긴 특이사항의 줄바꿈과 행 높이를 조절합니다.
- 데이터가 없는 날짜의 시트 생성 여부를 선택할 수 있게 합니다.
- 연도를 넘기는 기간에는 시트명 충돌을 피하고, 파일명에 양쪽 연도가 드러나도록 합니다.
- 다운로드한 파일을 Excel에서 열어 한글, 시간, 줄바꿈, 인쇄 미리보기를 검증합니다.

## 6. 기술 구성 제안

| 영역 | 제안 |
| --- | --- |
| 화면 | HTML·CSS·JavaScript 기반의 정적 웹 앱 |
| 엑셀 처리 | ExcelJS를 우선 검토하고 실제 참고 양식으로 읽기·쓰기 호환성 확인 |
| 배포 | GitHub Pages |
| 데이터 처리 | 사용자 브라우저 메모리에서 수행 |
| 설정 보관 | 개인정보가 없는 변환 규칙·출력 설정만 선택적으로 브라우저에 저장 |
| 작업 이어하기 | 후속 기능으로 작업 파일 내보내기·다시 불러오기 검토 |

ExcelJS는 브라우저용 워크북 처리와 XLSX 읽기·쓰기, 서식 및 인쇄 설정을 문서화하고 있습니다. 참고 양식과의 실제 호환성을 검증한 뒤 라이브러리 버전을 고정합니다. [ExcelJS 공식 문서](https://github.com/exceljs/exceljs#browser)

한 번만 쓰는 짧은 로직은 인라인으로 작성합니다. 재사용이 필요하거나 분기·예외 처리 때문에 흐름이 복잡해질 때만 함수를 분리하고, 초기부터 불필요하게 많은 모듈을 만들지 않습니다.

## 7. 파일과 배포 관리

현재 위치를 새 프로젝트의 루트로 사용하고, 기존 자료는 분석용으로 보관합니다. 다음 구조에서 README 이외의 새 웹 파일은 아직 생성하지 않았습니다.

```text
ganadara/
├── README.md          # 프로젝트 설명과 설계
├── index.html         # 웹 화면, 구현 예정
├── src/               # 화면·변환·출력 코드, 구현 예정
├── .github/workflows/ # 배포 자동화, 필요 시 추가
├── sg_pj-main/        # 기존 프로그램
└── 참고/              # 로컬 분석용 원본과 목표 파일
```

실제 발주 파일에는 신부명과 행사 정보가 있으므로 공개 저장소·배포 파일에 포함하지 않습니다. 배포 구성 시 기존 프로그램, 계정 파일, 참고 엑셀, 작업 파일을 제외하고 웹 앱에 필요한 파일만 배포합니다. 공개 테스트에는 가상 데이터를 사용합니다.

브라우저에서 선택한 엑셀 내용은 서버로 전송하지 않는 구조로 구현합니다. 새로고침 시 편집 내용이 사라질 수 있으므로 다운로드 전 화면에서 안내하고, 작업 저장 기능은 별도로 설계합니다.

## 8. 개발 순서와 완료 기준

### 1단계: 입력과 기본 출력

- [ ] 여러 파일·시트 읽기와 열 이름 판별
- [ ] 본식·촬영 구분 및 날짜 지정
- [ ] 참고 형식의 날짜별 본식 시트와 촬영 시트 생성
- [ ] 원본 값을 유지한 엑셀 다운로드

### 2단계: 수작업 정리 자동화

- [ ] 발주 합치기 후보와 원본 비교 화면
- [ ] 부케명 변환 규칙, 배송지·특이사항 편집
- [ ] 행 추가·제외·분리 및 순서 변경
- [ ] 출력 열·서식·파일명 설정

### 3단계: 검증과 배포

- [ ] 입력 건수와 합치기·제외 후 출력 건수 대조
- [ ] 동명이인, 추가금 발주, 재입력, 상충하는 값 처리 검증
- [ ] 날짜 누락, 여러 날짜 파일, 연도 변경 처리 검증
- [ ] 원본에 없는 정보가 임의로 채워지지 않는지 확인
- [ ] 다운로드 파일의 값·서식과 Excel 인쇄 결과 확인
- [ ] GitHub Pages에서 불러오기부터 다운로드까지 검증
- [ ] 공개 배포물에 원본 데이터·계정 정보가 없는지 확인

현재 제공된 파일로는 9월 12일 본식의 그룹 대응과 편집 동작을 우선 검증합니다. 다른 날짜·촬영의 전체 변환 검증에는 해당 입력 예시가 필요합니다.

## 9. 업무 규칙으로 확정할 항목

1. 여러 발주를 한 행으로 합칠 기준과 추가금·추가상품의 표시 방식
2. 상품 등급·코드에서 최종 부케명으로 바꾸는 기준 및 별도 요청의 입력 방식
3. 배송시간 계산 규칙의 유무와 `확인필요` 해제 조건
4. 출처별 플래너명 표기, 기본 정렬 순서, 서식의 색상 의미
5. 여러 날짜 원본에서 행별 행사 날짜를 확보하는 방법
6. EXE를 완전히 대체할 경우 사용할 공식 데이터 조회·다운로드·연동 경로

이 항목들은 후속 구현에서 확인하며, 그 전에는 자동 추정값을 확정 데이터로 취급하지 않습니다.
